# 资产申请抢修码

资产申请采用邮箱抢修码授权。用户提交申请后，仅按所选流程的第一级规则确定审批人；每位审批人收到一个独立的六位数字抢修码。申请人在“我发起的”页面点击“输入抢修码”，输入任一审批人提供的码，即完成整张工单授权。

## 行为

- 申请时必须填写资产或节点、账号、权限和起止时间；审批人必须有有效邮箱，系统必须已配置邮件服务器。
- 多级流程只在新建资产工单时取第一级，其余工单类型的审批流程保持原样。
- 抢修码只匹配当前登录申请人及对应工单，允许以 `0` 开头。失效时间为申请的授权结束时间。
- 校验成功后创建原工单申请的授权，关闭工单，并使该工单所有抢修码失效。授权开始时间仍按申请内容执行。
- 取消、拒绝、过期、已完成的工单均不能兑换。校验限流为每用户每分钟 5 次、每小时 20 次。
- 数据库仅保存以申请人 ID 和服务器密钥计算的摘要；抢修码只出现在发给审批人的邮件中，不进入站内信、抄送通知和工单接口。
- 授权、用户绑定、工单状态、码的消费在同一个数据库事务内完成，失败整体回滚。审核记录保留提供码的审批人与实际兑换的申请人。
- 资产申请的页面同意、批量同意和邮件直批入口均不能绕过抢修码。

## 上线

1. 在正确的 Core 环境执行 `python apps/manage.py migrate`，应用 `tickets.0008_ticketrepaircode`。
2. 编译后端翻译 `python apps/manage.py compilemessages -l zh`，更新 Core 和 Celery 进程。
3. 在 Lina 执行 `yarn build:prod`，发布前端产物。
4. 核验 SMTP、审批人邮箱及 Celery 邮件任务可用。用新建工单验证真实收信，再输入码确认用户资产权限。

升级前的待处理资产工单没有抢修码，需要取消后重新申请。迁移不会改写、撤销或自动授权历史工单；已经生成的资产授权不受影响。

## 验证

后端用例：`python apps/manage.py test tickets.tests`。覆盖申请、邮件内容与收件人、兑换后的授权范围、重复兑换、越权、过期、回滚、限流和并发兑换；本次已在 MySQL 上验证两个并发请求只完成一次授权。

前端检查：`yarn lint`、`yarn build:prod`。
